## Catatan rekonsiliasi (dua rencana berbeda granularitas)

Sebagian scope Day 01-20 di bawah ini sudah punya implementasi nyata, tetapi dikerjakan lewat rencana lain yang lebih kasar granularitasnya: `docs/superpowers/plans/2026-07-17-trareon-acquire-foundation.md` (8 task, single-author Claude Code, tanpa siklus review Codex per-Day yang dijelaskan runbook ini). Kode Task 1-8 asli sudah di-merge ke `main` lewat PR #32. Commit gap-fill Day 06/07/10/11/15/17-19 sempat ter-push ke branch yang sama **setelah** PR #32 ditutup/merged, sehingga sempat nyangkut tanpa PR yang melacaknya — kemudian dilandaskan dan di-merge lewat https://github.com/Trareon-com/Trareon-Acquire/pull/33, frozen SHA `bad982f5218df5e5a7b39bc4f47d7b2a24a5827f`.

Kolom `Implementation` untuk Day yang scope-nya cocok diberi nilai `IMPLEMENTED_UNREVIEWED` — artinya kode ada, teruji lokal (`cargo test --workspace --locked`, `cargo clippy -D warnings`, `cargo fmt --check` semua hijau; untuk Day 20 juga `npm ci`/`npm run build`), dan sudah di-push, tetapi **belum** melalui independent review Codex atau human approval yang disyaratkan runbook ini.

CI GitHub untuk PR #33 pada commit `bad982f5218df5e5a7b39bc4f47d7b2a24a5827f` sudah **PASS di ketiga OS** (ubuntu-latest, windows-latest, macos-latest) — lihat `test (ubuntu-latest)`, `test (windows-latest)`, `test (macos-latest)` pada https://github.com/Trareon-com/Trareon-Acquire/pull/33/checks. Sebelumnya di PR #32, tiga kegagalan nyata ditemukan dan diperbaiki di root cause-nya (bukan disembunyikan): (1) ubuntu-latest gagal karena system dependency Tauri (`libwebkit2gtk` dkk) belum ter-install lewat apt di `ci.yml`; (2) windows-latest gagal karena `apps/trareon-acquire/src-tauri/icons/icon.ico` belum ada — tauri-build butuh itu untuk Windows Resource file; (3) windows-latest gagal lagi dengan "Access is denied (os error 5)" karena `copy_and_sync()` di `package.rs` membuka file hasil copy dengan `File::open()` (read-only) lalu memanggil `.sync_all()` — di Windows, `FlushFileBuffers` butuh write-access handle. Di PR #33 ditemukan kegagalan keempat: `windows-latest` gagal `golden_valid_package_is_accepted` (exit 2, seharusnya 0) karena repo tidak punya `.gitattributes` — checkout Windows mengonversi LF→CRLF pada fixture `fixtures/fsnap-v0.1/**`, merusak byte content yang hash SHA-256/audit-root-nya sudah dibekukan di manifest. Diperbaiki dengan menandai seluruh `fixtures/fsnap-v0.1/**` sebagai `-text` di `.gitattributes`.

Kolom `Review` dan `Human Gate` tetap `NOT_STARTED`/`NOT_REQUIRED` karena independent review Codex dan human approval belum terjadi — hosted CI hijau bukan pengganti keduanya.

Catatan disiplin proses: perbaikan di atas dilakukan dalam 3 push berturut sebelum semua OS hijau, melebihi batas "maksimal dua recovery cycle" yang disyaratkan runbook ini untuk task lain (lihat `Unexpected-Output Routing` di tiap `DAY-NN.md`). Karena Day 20 dikerjakan lewat Foundation Plan yang terpisah, bukan lewat runbook Day-by-day ini, aturan itu tidak diberlakukan secara otomatis di sini — tetapi dicatat agar tidak dianggap sesuai proses baku tanpa syarat.

## Milestone gates

- **Week 1:** deterministic state/audit foundations, clean integration, zero unresolved P0/P1.
- **Week 2:** byte-accurate synthetic acquisition, safe package, independent verifier, `.fsnap` v0.1 draft.
- **Week 3:** core-owned UI state, guidance, report, three-OS hosted CI, DevSecOps, fuzz/property baseline.
- **Day 30:** `.fsnap` v0.1 golden compatibility fixtures, verifier independence, limitation matrix, performance baseline, complete evidence index, human classification approval.

Day 30 hanya boleh menjadi `Production-Directed Engineering Alpha Candidate — Lab Use Only`. Semua capability tanpa exact hardware evidence tetap `NotValidated`.
